# HwSim ancestry and CMS fiducial v3

The optional HwSim output records the actual parent and copy links of stable
electrons, muons and photons. The CMS v3 analyzer selects direct hard-process
or H/Z/W-origin electrons and muons, excluding tau and hadron daughters. A
direct hard lepton is allowed because continuum LHE records need not contain
an intermediate Z. Photon dressing requires the emitting lepton's lineage
and delta-R < 0.3. Only that lepton's assigned FSR is removed from its isolation;
hadronic photons contribute normally. GEM/SSC reconstruction is unchanged.

The physics convention follows the [CMS fiducial definition, section 10.2](https://arxiv.org/pdf/1706.09936)
and is cross-checked against the [public Run-2 implementation](https://github.com/lucien1011/UFHZZAnalysisRun2/blob/84a1d5220218627437a86bf9a2c55c6b7f49796c/UFHZZ4LAna/src/UFHZZ4LAna.cc#L4103).
The public implementation is supporting evidence, not proof of the exact
revision used for the published acceptance table. Exact lineage association
also avoids assigning one photon to several nearby same-sign leptons.

## Private build on Timur

```bash
module load herwig/stable
python3 hfourlepton/hwsim/build_plugin.py \
  --source-repo /home/shared/Herwig/src/Herwig-7.3.0/Contrib/hwsim \
  --output-dir inputs/pipeline/hwsim-ancestry-v1
```

The builder reads HwSim Git revision
`51ba33aea55ddbee0df8309d425b6fbdde1ceee3`, applies the tracked patch and records
the compiler command, source hashes and library hash in `build.json`. It does
not use local modifications in the source checkout or install a shared library.
Use a new output directory if a failed build or a different version is present.

The library is deliberately named **HwSimAncestry.so**. Herwig serializes its
library search paths in `.run` files; reusing the name `HwSim.so` can load the
old shared plugin despite a private path at `Herwig read` time. The ancestry
analyzer rejects missing branches, including mixed old/new ROOT input lists.

## Revalidate a completed 13 TeV campaign

```bash
python3 run_pipeline.py reprocess --workflow fourlepton-ho --energy-tev 13 \
  --run-tag YOUR_COMPLETED_RUN --revision cms_v3 --jobs 8 \
  --ancestry-plugin-dir inputs/pipeline/hwsim-ancestry-v1
```

This repeats the original seeded showers using the existing production and
MadSpin LHE files, then runs the strict report, CMS acceptance comparison,
cut analysis and XGBoost analysis. Each sample must reproduce the original
shower counts and signed weight moments. The original normalization, including
ihixs for ggF and failed showers' zero response, is unchanged. Completed products
are written under `revisions/cms_v3`; partial attempts are preserved and the
same command resumes completed samples. No hard events are generated by this
command. Acceptance and statistical requirements are unchanged.

For a parent manifest that is itself an analysis revision, invoke the helper
inside the Herwig environment:

```bash
PYTHONNOUSERSITE=1 inputs/pipeline/venv/bin/python hfourlepton/reprocess.py \
  --manifest PATH_TO_PARENT_MANIFEST --output-dir NEW_REVISION_DIRECTORY \
  --ancestry-plugin-dir inputs/pipeline/hwsim-ancestry-v1 --jobs 8
```

Omitting `--ancestry-plugin-dir` continues to support the old operation of
reading saved showers with CMS v2. It cannot supply missing particle history
or establish the ancestry-aware comparison.

## ROOT schema 1

Enable both `SaveObjects Yes` and `SaveAncestry Yes`. Existing object fields
and jet/b-hadron labels keep their meaning. The additional branches are:

| Branch | Meaning |
|---|---|
| `truthSchemaVersion` | Integer 1 |
| `truthObject` | One graph index per saved object; -1 except e/mu/photon |
| `truthPdg` | Signed PDG code of each graph node |
| `truthParents` | Flattened parent indices |
| `truthParentOffsets` | Node i's parents occupy offsets i through i+1 |
| `truthPrevious` | ThePEG previous-copy index, or -1 |
| `truthHard` | 1 for primary outgoing particles, 2 for primary incoming, otherwise 0 |

All ancestors of the selected stable species are recorded, including hadrons
and taus. Graph traversal is iterative and cycle-safe. Classification stops
at the first non-copy parent rather than treating the ancestral beam proton
as a nonprompt origin. `objects` arrays are guarded against overflow at 10,000
stable particles. Persistent class version 2 adds the optional switch; old
configurations default to no ancestry output.

The analyzer records `cms_fiducial_v3` and `ancestry_schema_version=1` in both
ROOT metadata and the JSON summary. The revision manifest includes the private
plugin and build-provenance checksums.
